## 1. 设计前提：信号由写好的代码产生，Claude 不临场判断

“Claude 出信号”要落地成：**信号由写成代码、带版本号、能回测的策略产生。Claude 负责设计、写代码、复核和解释，不每天临场判断。**

1. **Claude 的临场判断没法回测。** 模型的训练数据里已经有历史行情后来怎么走，让它判断 2023 年的 K 线，等于看着答案考试。而且同样的输入，两次回答可能不一样，无法复现。
2. **Claude 不是常驻进程，只在开会话时运行。** MT5 需要一个 24×5 常驻的执行程序，放在一台一直开着的 Windows 机器或 VPS 上，和 MT5 终端一起运行。硬性风控写死在代码里，不能靠提示词。
3. **GitHub 上把 Claude 接进 MT5 的项目也是这么做的。** liumou/ai-trading-agent 默认由确定性策略出信号，Claude 只做确认闸门（它的“AI 自主模式”不建议用）。mt5-trade-split-manager 暴露给 Claude 的 MCP 工具默认只读，要显式设置 `MT5_MCP_ENABLE_TRADING=1` 才能下单，而且每笔单必须带止损。

## 2. 整体架构

- **LEAN 的五段流水线**：选品种（Universe）→ 出信号（Alpha，产出 Insight）→ 组合构建（转成目标仓位 PortfolioTarget）→ 风控（调整或削减目标）→ 执行。三条通道只有最后的执行段不同：A 股和期货是把信号推送给浩哥手动下单，MT5 是执行器自动下单。前四段三个市场共用。
- **Hikyuu 的系统部件**：市场环境判断 EV、系统有效条件 CN、信号指示器 SG、止损 ST、止盈 TP、资金管理 MM、盈利目标 PG、滑点 SP、交易对象选择 SE、资金分配 AF、交易管理 TM。每个部件都能单独替换、单独评估，能分清到底是信号起了作用，还是止损或仓位起了作用。
- **信号用目标仓位表达**（参考天勤 TargetPosTask、LEAN PortfolioTarget）：不说“买 3 手”，而说“目标持有空 3 手”。漏执行一次，下一次信号依然正确；部分成交、手动调整之后，系统自动算差额。这一点对人工执行最重要。
- **回测和实盘用同一份策略代码**，这是 NautilusTrader 和 vn.py 的核心卖点，也正是当前项目缺的（见《交易员视角评审》2.1）。

## 3. 成本和撮合

### 3.1 各市场要算的成本

| 市场 | 成本项 | 取值和校准 |
|---|---|---|
| A 股 | 佣金 | 按自己券商的实际费率，确认是否免五（最低 5 元） |
| A 股 | 印花税（只在卖出时收） | 2023-08-28 之前 0.1%，之后 0.05%，按成交日期取值 |
| A 股 | 过户费（买卖都收） | 2022-04-29 之前 0.002%，之后 0.001% |
| A 股 | 执行损耗 | 实际成交价 − 信号参考价。先假设 0.1–0.2%，再用自己的真实成交统计替换 |
| A 股 | 成交不了的情况 | 涨停买不到，跌停卖不出，停牌 |
| 期货 | 手续费 | 按品种区分固定金额或按成交额收，平今仓可能不同；等于交易所收费加期货公司加收 |
| 期货 | 滑点 | 手动执行先按 1–2 跳，再用真实成交校准 |
| 期货 | 换月成本 | 平旧、开新共两次手续费、两次滑点，再加两个合约的价差 |
| 期货 | 其他 | 保证金占用、停板时平不了仓、节前交易所提高保证金 |
| MT5 | 点差 | 买用 Ask，卖用 Bid；回测用逐根 K 线的 spread 列 |
| MT5 | 佣金 | ECN/Raw 类账户按手收取 |
| MT5 | 隔夜利息 | `symbol_info` 里的 `swap_long` / `swap_short`；收三倍的那天看 `swap_rollover3days` |
| MT5 | 滑点 | `order_send` 返回的成交价减去请求价 |
| MT5 | 实际成本核对 | `history_deals_get` 每笔成交都带 `commission`、`swap`、`fee` |
| MT5 | 币种换算 | 用 `order_calc_margin` / `order_calc_profit` |

> 更正：上次体检脚本 `scripts/audit_signal_quality.py` 的印花税全程按 0.05% 计算，2023-08-28 之前实际是 0.1%。所以那段时间的成本被低估了，真实结果只会更差。

### 3.2 撮合规则

- **vn.py 回测引擎**（`vnpy_ctastrategy/backtesting.py`）
  - 每根新 K 线的处理顺序：先撮合挂单 `cross_limit_order` / `cross_stop_order`，再调用 `strategy.on_bar`。所以 `on_bar` 里下的单，一定要到**下一根 K 线**才会撮合，不可能按当根收盘价成交。
  - 买入限价单的成交条件：下一根 K 线最低价 ≤ 限价。成交价 = `min(限价, 下一根开盘价)`。更保守的做法是要求最低价 < 限价（价格穿过去才算），因为价格碰到限价时，排队的单不一定轮到你。
  - 成本参数：`rate`（费率）、`slippage`（每单位滑点）、`size`（合约乘数）、`pricetick`（最小变动价位）。
  - 手续费 = 成交额 × rate；滑点 = 手数 × 乘数 × slippage。
  - 回测报告里 `total_commission` 和 `total_slippage` 单独列出，还有最大回撤百分比、最长回撤天数、夏普、收益回撤比等。
- **RQAlpha 的 A 股撮合**（`rqalpha_mod_sys_simulation`）
  - `matching_type`：可选 `current_bar`、`next_bar`、`vwap` 等。
  - `price_limit=True`：涨跌停价不成交。
  - `inactive_limit=True`：当根 K 线成交量为 0（停牌）时不成交。
  - `volume_limit=True` + `volume_percent=0.25`：每根 K 线最多成交市场成交量的 25%。
  - `slippage_model`：`PriceRatioSlippage`（按比例）或 `TickSizeSlippage`（按跳）。
- **RQAlpha 的交易成本**（`rqalpha_mod_sys_transaction_cost`）
  - `stock_min_commission=5`：最低佣金 5 元。
  - `pit_tax`：按回测日期使用当时的印花税率，也就是“成本参数按历史时点取值”。
- **Qlib 的示例配置**：`limit_threshold=0.095`，`deal_price`，`open_cost=0.0005`，`close_cost=0.0015`，`min_cost=5`。
- **LEAN 的真实性模型清单**：建系统时逐项核对是否已经建模：
  - 成交模型、滑点模型、手续费模型；
  - 券商规则模型、购买力/保证金模型；
  - 结算模型（T+1）、做空可借性；
  - 融资利息、追保强平。
- **NautilusTrader**（2.0.0rc5）：`BacktestVenueConfig` 支持 `fill_model`、`fee_model`、`latency_model`、`liquidation_enabled`；支持 OCO、OTO 等条件单。

### 3.3 人工执行的执行损耗

人工执行比程序多一项成本：**实际成交价 − 信号参考价**，其中还包含下单延迟。

- 每笔都记下来，一两个月后按品种统计分布，用 75 分位数作为回测的滑点假设。
- 回测里的撮合方式要和人实际的执行方式一致：信号说“次日集合竞价限价 ≤ X”，回测就按“次日开盘价 ≤ X 才成交”来算。

## 4. 防未来函数、防过拟合

- **freqtrade lookahead-analysis**：先跑一次完整回测作为基准，再截断数据重跑，对比每个信号和指标值有没有变化。变了，就说明用到了未来数据。
- **freqtrade recursive-analysis**：换不同数量的预热 K 线（startup candles）重算指标，看最后几根的值差多少。EMA、RSI 这类递推指标常有这个问题。
- **pybroker**：滚动前推验证（walk-forward），加上 bootstrap 置信区间，报告出来的不是一个孤立的数字，而是“夏普及其 95% 区间”。
- **Qlib**：训练、验证、测试按时间切成三段（示例：2008–2014 / 2015–2016 / 2017–2020），用 IC 分析检验因子。
- **liumou/ai-trading-agent 的思路**：
  - 蒙特卡洛：随机打乱交易顺序，看回撤分布；
  - 置换检验：判断结果是不是运气；
  - 过拟合综合评分。
- 这些检查都可以写进回测流程里自动跑，不通过的规则不能进入信号推送或自动交易。

## 5. 风控规则汇总

| 层级 | 规则 | 来源 |

## 6. 三条执行通道

### 6.1 A 股：Claude 出信号，浩哥手动执行

- **节奏**：日线信号在收盘后生成，次日集合竞价或开盘后限价执行。这是人手能跟上的节奏，回测也按同样的方式撮合。
- **对账**：
  - 开通 MiniQMT 后，用 xtquant 或 easytrader 的 miniqmt 模式（`balance`、`position`、`today_entrusts`、`today_trades`）**只读**拉取持仓和成交。手机上下的单能不能查到，开通后要实测确认。
  - 没开通 MiniQMT 时，每天导入交割单。
- **交易日历**：用 exchange_calendars 的 XSHG。
- **推送**：参考 freqtrade 的 Telegram 控制方式，用小云（Telegram/微信）推送信号单；浩哥回复成交情况，系统解析后入账。

信号单模板：

```yaml
signal_id: SIG-20260922-600000-01
strategy: trend_daily_v3 @ git a1b2c3d     # 策略名 + 代码版本，保证可复现
generated_at: 2026-09-21 15:40 北京时间
instrument: 600000.SH 浦发银行
target_position: 3000 股                     # 目标持仓，而不是“买多少”
system_position: 0 股                        # 系统记录的持仓；与账户不符时先对账
action: 买入 3000 股
execution: 次日 9:15–9:25 集合竞价限价 ≤ 9.15；未成交则 9:30–10:00 限价 ≤ 9.15，过时作废
reference_price: 9.07                        # 信号收盘价，用来计算执行损耗
stop: 收盘价 < 8.72 → 次日开盘卖出
risk: 按最差可接受成交价 9.15 计算，最多亏约 1,290 元（权益的 0.13%）
reason: 趋势评分 xx；大盘过滤通过；……
valid_until: 2026-09-22 10:00
```

回报格式：`回报 SIG-20260922-600000-01 买 3000 @ 9.09 09:25`。系统据此算出执行损耗 =（9.09 − 9.07）/ 9.07 ≈ 0.22%。

### 6.2 国内期货：Claude 出信号，浩哥手动执行

- **信号用主力连续，下单用具体合约**：
  - 连续序列要做价差调整，可以参考天勤的 `KQ.m@SHFE.rb`，以及 wtpy 的 WtHotPicker（按交易所数据确定换月）+ hots.json（主力合约映射表）。
  - 移仓计划提前写进信号单。
- **正式交易前**：先用 SimNow 或天勤的模拟账户（实时行情）手动执行 1–3 个月，量出自己的执行损耗。
- **规则**：夜盘成交归属下一交易日；区分平今和平昨的手续费；自然人账户必须在进入交割月之前移仓。

信号单模板：

```yaml
signal_id: SIG-20260922-RB-01
strategy: trend_fut_v2 @ git a1b2c3d
instrument: RB2601（当前主力；信号基于价差调整后的主力连续序列）
target_position: 空 3 手
system_position: 0
action: 卖开 3 手
execution: 当晚夜盘 21:00–21:15 限价 ≥ 3090；未成交作废
reference_price: 3096
stop: 3148（止损条件单，触发后对价平仓）
roll_notice: 11 月第 2 周移仓到 RB2605
risk: 按最差成交价 3090 计算，最多亏 (3148 − 3090) × 10 × 3 = 1,740 元
valid_until: 2026-09-22 21:15
```

### 6.3 MT5：执行器自动下单

执行器检查清单：

1. **启动**：
   - 连接终端；
   - 确认账户类型（Demo 还是 Real）与配置一致；
   - 对账：持仓、挂单和本地记录一致之后，才允许交易。
2. **收到每个信号**，按以下顺序检查，任何一步不通过就拒单：
   1. 幂等键去重；
   2. 当前在允许的交易时段内（参考 aiomql Sessions）；
   3. 不在新闻窗口内；
   4. 点差不超过上限；
   5. 风控通过：每笔风险、组合总风险、日亏损、最大持仓；
   6. 计算手数：向下取整到 `volume_step`，低于 `volume_min` 就拒单；
   7. 止损距离 ≥ `trade_stops_level`；
   8. `order_check` 通过；
   9. `order_send`，请求里带上 `sl` / `tp`、`deviation`、`magic`，`comment` 填信号编号。
3. **成交后**：记录请求价、成交价、滑点、点差，以及 `commission`、`swap`、`fee`（通过 `history_deals_get` 获取）。
4. **运行中**：
   - 心跳检查，断线就暂停；
   - 触发日亏损上限后只允许平仓；
   - 周五收盘前按规则处理隔夜仓；
   - 保留紧急停止开关。
5. **权限**：
   - 只有一个桥接进程能直接操作 MT5（参考 liumou 项目），其他模块都通过它下单；
   - Claude 通过只读 MCP 工具查看账户和日志、做复核，没有下单权限。

## 7. 不建议照搬的

- **vn.py / WonderTrader**：功能最全，但体量重，以 CTP 为主，官方不支持 MT5。借鉴它们的规则就好，不要整套搬过来。
- **RQAlpha**：许可证仅限非商业使用。学它的 A 股撮合规则就够了。
- **Qlib**：做多股票因子研究很强，拿来做单品种择时是杀鸡用牛刀。
- **freqtrade**：只支持加密货币。学它的防偏差工具和暂停机制。
- **GitHub 上“AI/Claude + MT5”的项目**：关注度低，也没经过验证，只借思路，不要直接拿来跑真钱，尤其不要用“AI 自主决策”模式。
